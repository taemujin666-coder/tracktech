# M1.1 — Evidence-First Incremental Import

## Decision record

TrackTech uses the workbook as an input, not as an implicit source of truth for facts that are absent. `Complaint Log` supplies evidence-backed complaint cases. The derived Complaint/Rework columns in `Job Data` are not used to manufacture cases.

## Source mapping

| Sheet | Stored | Deliberately excluded |
|---|---|---|
| Job Data | Order number, install date, product/model, source Tech ID, project/vendor, QC date/result, job status | Customer name, free-text note, derived complaint/rework flags |
| Complaint Log | Dates, source Tech ID, issue evidence, QC result, root-cause fields, actions, rework/service mind, owner, case status | Technician name copied from the case row |
| Technician Master | Tech ID, normalized name, team, vendor, source status, area | Empty presentation columns |

## Identity and reconciliation

| Condition | Result |
|---|---|
| Tech ID exists in Technician Master | `VERIFIED`; eligible for a profile |
| Blank Tech ID | `MISSING_TECHNICIAN_ID`; job retained |
| `PWS1` or `PWS51` | `UNVERIFIED_TECHNICIAN_IDENTITY`; volume retained, no profile/score |
| Other ID absent from master | `PENDING_MASTER_MATCH`; requires confirmation |
| Complaint Order No. absent from current Job Data | `JOB_NOT_FOUND`; case retained |
| Complaint Tech ID differs from all Job Data rows for that order | `TECHNICIAN_CONFLICT`; human review, no automatic attribution |

## QC semantics

An explicit QC result is `RECORDED`. A blank result on `Not Complete` becomes `NOT_APPLICABLE_NOT_COMPLETE`; a blank result on `Cancel` becomes `NOT_APPLICABLE_CANCELLED`. Any other blank result is `MISSING_SOURCE_VALUE`. These labels describe the source evidence and do not claim whether a person performed a check.

## Incremental behavior

Each source row receives a deterministic key. Job keys use normalized Order No., install date, product/model, and occurrence number. Complaint keys use normalized Order No., complaint date, and occurrence number; status/action changes therefore update the same case.

The PostgreSQL adapter performs upserts in one transaction:

1. Create an `import_runs` audit row.
2. Insert/update verified Technician Master records.
3. Insert/update Job rows by `source_job_key`.
4. Insert/update Complaint cases by `source_case_key`.
5. Store inserted, updated, skipped/unchanged, conflict, and unmatched counts.

No delete statement is part of the import. An older case remains even when a later workbook omits it.
